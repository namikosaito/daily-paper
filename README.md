# Physical AI Daily

arXiv掲載論文を、毎日3本×5カテゴリで紹介するサイトです。PCでは3列×5行、スマートフォンでは1列で表示します。

| 行 | 内容 | 選定 |
|---|---|---|
| 1 | 関心に近いRobot Learningの新着 | 昨日・今日（日本時間）を優先 |
| 2 | 関心に近いRobot Learningの高引用論文 | 発表年を問わず引用数順 |
| 3 | ロボティクス全般の高引用論文 | 発表年を問わず引用数順 |
| 4 | AI・機械学習・Computer Visionの新着 | 昨日・今日（日本時間）を優先 |
| 5 | AI・機械学習・Computer Visionの高引用論文 | 発表年を問わず引用数順 |

新着枠が3本に満たない場合は直近7日から補充し、カードに明記します。それでも不足する場合は空き枠を表示し、無関係な論文や架空の引用数で埋めません。同一日・過去掲載日を通じてIDの重複掲載を除外します。

## データと選定基準

- タイトル・著者・公開日・抄録・本文・PDFはarXivから取得します。公開日は初版の日付を使います。
- 引用数だけはSemantic Scholar Academic Graph APIから取得し、出典と確認日を保存します。高引用枠は30引用以上を対象とします。
- 引用数は品質・正確性・査読済みを保証する指標ではありません。経過年数・分野の影響も受けます。
- 高引用候補は検索クエリごとの引用数順結果から、arXiv ID付きの上位100件を取得して検証します。世界中の全論文を網羅したランキングではありません。
- 新着は各検索の最大300件から選びます。AI枠はcs.AI、cs.LG、cs.CV、cs.CL、cs.NE、stat.MLを対象とします。
- 関心枠はVLA・残差RL・Sim-to-real、視覚/力覚/触覚のマルチモーダル学習、接触操作、変形物・道具の操作、サブゴール・長期動作生成、人との協調・再計画を優先します。
- テーマ別キーワードと重みは [`config.json`](./config.json) で変更できます。意味的類似度を学習する方式ではなく、キーワードと分野による選定です。
- 通信障害・API制限・要約失敗時はエラー終了し、既存アーカイブを保持します。候補不足とAPI障害は区別します。

## 著者・所属・図

著者と、**論文に記載された所属**を一覧・詳細に表示します。所属はarXiv API・HTMLの所属欄・PDFの1ページ目から取得します。HTMLの所属欄に含まれるプロジェクトURLは除外します。著者の現在の所属やメールドメインから推測しません。取得できない場合は「所属未確認」とします。PDF抽出は保守的なため、判読できる所属でも認識できない場合があります。所属は論文単位の一覧で、著者別対応を推測しません。

図はCC BY / CC BY-SA 3.0・4.0、またはCC0を確認できる場合に取得し、著者・出典・元のライセンスを詳細ページに表示します。

1. HTML版の図を1枚取得
2. 取得できなければPDFを画像化。先頭5ページからFigure 1に言及する最初のページを選び、なければ1ページ目を使用
3. PDF画像には「ページプレビュー・図の切り抜きではない」と明記

スクリーンショットでも再利用条件は変わりません。許可を確認できない場合は図なしで原論文にリンクします。PDF画像は最大1800px、PDF取得は40MBまでに制限します。

**日本語要約は抄録だけが根拠です。** PDFは図と所属の取得に使用しますが、本文を読んだ要約・査読確認・メール通知は行いません。

## 日本語のまとめ方

詳細ページは次の5項目で、専門用語や略語も簡潔に説明し、わかりやすく丁寧にまとめます。

- **要約**：何をどう解決する研究かを端的に。100〜200文字程度、最大240文字。
- **優位点・独自点**：従来との違いや利点。著者の主張と比較実験で確認された結果を区別。
- **技術や手法のキモ**：入力・処理・出力と、中心となる工夫が役立つ理由。
- **検証方法**：評価対象、実験条件、比較方法、評価指標。抄録にない実験や数値は補わない。
- **今後の課題**：記載された限界や課題。記載がなければその旨を示し、追加確認事項と著者の主張を区別。

情報が少ない項目も省略せず、抄録では確認できないことを明記します。一覧カードには短い要約を表示し、詳細の各項目も検索対象にします。

## ローカル起動

Node.js 24以上が必要です。

```sh
cd daily-paper
npm ci
npm exec -- copilot login
npm run digest
npm start
```

このMacでプロジェクト内のNode.jsを使う場合は、先に次を実行します。既存のNode.jsは変更していません。

```sh
export PATH="$PWD/.tools/node-v24.22.3-darwin-arm64/bin:$PATH"
```

ブラウザで **http://localhost:4173** を開きます。発行後は再読み込みしてください。サーバーはループバックだけで待ち受け、公開ファイルと図以外は配信しません。

```sh
npm run preview             # 要約なし。arXiv・引用数・図・所属だけ取得
npm run figures             # 掲載済み論文の図・所属を取得・再試行。Copilotは呼ばない
npm run digest -- --refresh  # 当日分を再選定。新しく選んだ論文だけ要約
npm test
npm run build:site          # 公開ファイルだけをdist/へ出力
```

プレビューは **http://localhost:4173/?preview=1** に表示し、本番アーカイブには追加しません。当日分の再選定に成功した場合だけ置き換え、過去日は保持します。通常の再実行は同日号を再生成しません。ただし当日号の要約が旧形式なら、選定・図・所属を保持したまま不足分の要約を新しい5項目へ移行します。新形式への移行が完了していれば追加のCopilotリクエストは行いません。再選定でも旧形式の要約は再利用しません。旧5本構成・旧要約形式のバックナンバーも閲覧できます。

## Copilot・費用

Copilot CLIはVS Codeのターミナルでも使えるアプリですが、このチャットとは別の実行です。契約の利用枠を消費し、契約・設定により追加費用が生じます。無料利用を保証しません。15本構成は以前の5本構成よりリクエスト数が増え、最大3本ずつまとめて要約します。

公開論文のタイトル・抄録・タグだけを渡し、ファイル操作・シェル・外部検索ツールを無効化した一時ディレクトリで実行します。JSONLイベントの正常終了・最終応答、件数・ID・見出しと5項目の日本語・要約の文字数を検証します。失敗時の診断はGit対象外の `.run/last-copilot-response.txt` に保存します。

認証情報をコード・アーカイブ・チャットに貼らないでください。[CLIの認証方法](https://docs.github.com/en/copilot/how-tos/copilot-cli/set-up-copilot-cli/authenticate-copilot-cli)も確認してください。

Semantic Scholar APIはキーなしでも試せますが、制限時は429応答を再試行します。安定した運用にはAPIキーを取得し、`SEMANTIC_SCHOLAR_API_KEY` 環境変数・GitHub Secretに設定できます。キーをリポジトリには保存しません。

## GitHub Pagesで公開・毎日自動更新

[`pages.yml`](./.github/workflows/pages.yml) は以下の動作をします。

- mainへのpush：テストし、現在のアーカイブを公開。Copilotは呼びません。
- 毎日21:00 UTC（翌日の日本時間6:00）／手動実行：論文を取得・要約し、公開データをコミットしてからPagesへ反映します。
- cronはGitHub側で遅延することがあります。公開リポジトリの定期実行は長期間操作がないと無効化される場合があります。
- 失敗時はActionsをエラーにして既存サイトを保持します。GitHubの失敗通知を有効にしてください。

### 必要なGitHub設定

1. 公開リポジトリにコードをpushする。
2. **Settings → Pages → Source** を **GitHub Actions** にする。
3. 個人アカウントで作成したfine-grained PATに **Copilot Requests** 権限を付け、**Settings → Secrets and variables → Actions** に **COPILOT_GITHUB_TOKEN** として登録する。Copilotを使えるアカウントのトークンが必要です。
4. 必要に応じて **SEMANTIC_SCHOLAR_API_KEY** も登録する。
5. **Actions → Publish daily papers → Run workflow** で確認する。既に当日分があれば追加要約はしません。

初回確認では `verify_copilot` を有効にすると、1本分の実要約リクエストで認証・利用枠を検証します（利用枠を消費）。`refresh` を有効にすると当日分を再選定し、クラウドからのarXiv・引用数・画像・所属取得も確認できます。通常の定期実行では、これらの手動確認用オプションは使いません。

Copilot Secretがなくてもpushによるサイト公開はできますが、毎日の更新・手動実行は認証不足として失敗します。Secretsの登録とクラウド実行の成功確認が済むまでは、自動更新が完成したとは扱わないでください。

公開するのはHTML/CSS/JS・`data/archive.json`・参照中の `figures/` だけです。`.tools/`・`.run/`・`node_modules/`・環境変数・ソース設定はPagesの公開物に含めません。GitHub Actions自体は公開リポジトリ内のコードを実行するため、外部PRのコードにSecretsを渡すトリガーは用意していません。

## Macで自動更新する場合

GitHubへの移行が完了するまでは、ローカル自動更新も使用できます。

```sh
npm run schedule:install
npm run schedule:remove
```

ログイン中15分ごとに日本時間を確認し、6時以降に当日分が未発行なら生成します。スリープ・電源OFF・ログアウト中は実行できず、復帰後に当日分だけを生成します。ログは `.run/schedule.log` と `.run/schedule-error.log`。クラウド運用を開始したらローカル登録を解除し、両方での別々の発行を避けてください。

登録ファイル：`~/Library/LaunchAgents/local.daily-paper.digest.plist`。ディレクトリ・Node.jsを移動する前に解除して再登録してください。

## データ

- [`data/archive.json`](./data/archive.json)：全バックナンバー、引用数の出典・確認日、図・所属の出典。削除すると掲載履歴も失います。
- `data/preview.json`：要約前のプレビュー。Git対象外。
- `.run/digest.lock/`：二重実行防止。異常終了で残った場合は `owner.json` のPIDが終了していることを確認し、このロックだけを削除してください。
